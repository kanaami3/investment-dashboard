# 要件定義書 — OANDA Japan デモ口座 ライブ運用

| 項目         | 値                                              |
|--------------|-------------------------------------------------|
| ドキュメント | 要件定義書 (Requirements)                       |
| プロジェクト | APS+MTF Signal — OANDA Live Deployment          |
| 対象環境     | OANDA Japan fxTrade Practice (デモ)             |
| 対象銘柄     | JP225_JPY (日経225 CFD)                         |
| 作成日       | 2026-05-23                                      |
| ステータス   | Draft v1                                        |

---

## 1. 背景・目的

`aps_mtf` パッケージで開発済みの APS pressure + MTF (M5/H1/D1) スコアリングロジックを、**OANDA Japan のデモ口座** で**実時間** (リアルタイム価格・実発注フロー) に流し、以下を達成する。

- **L1: ロジック移植性の検証**
  MQL5 EA / オフライン backtest / OANDA ライブの 3 経路で**同一スコア**が出ることを実データで確認する。
- **L2: 24/5 自動運用の信頼性検証**
  バーごとのポーリング・発注・ポジション管理が無人で連続稼働できることを確認する。
- **L3: ライブ口座昇格判断のデータ取得**
  デモ N 日間のシグナル発生数・勝率・最大ドローダウンを記録し、ライブ移行 GO / NO-GO 判定の材料とする。

> 本プロジェクトのスコープは **デモ口座での運用確立まで**。ライブ口座への金銭投入は別案件として扱う。

## 2. 用語

| 用語              | 定義                                                                |
|-------------------|---------------------------------------------------------------------|
| APS               | Aggregated Price Strength — 出来高加重した買い圧 / 売り圧             |
| MTF               | Multi-Time-Frame: M5 (エントリー) / H1 (中期) / D1 (環境認識)        |
| ランナー          | `aps_mtf.oanda.runner.LiveRunner` のループ                          |
| デモ口座          | OANDA Japan fxTrade Practice。仮想 JPY、実価格、実約定フロー         |
| ライブ口座        | OANDA Japan fxTrade。実資金。本プロジェクトのスコープ外              |
| ドライラン        | スコア計算と発注決定までは行うが、HTTP POST はしないモード           |
| バー確定          | 設定された granularity の足が終値で確定したタイミング (UTC基準)      |

## 3. ステークホルダー / 役割

| 役割             | 担当                | 主な責任                                                       |
|------------------|---------------------|----------------------------------------------------------------|
| プロダクトオーナー| 利用者本人          | パラメータ承認、ライブ昇格 GO/NO-GO 判定                       |
| 開発              | 利用者 + Claude     | コード変更、ロジック追加                                       |
| 運用              | 利用者本人          | デモ口座監視、CSV ログレビュー、トークン管理                   |
| 監査              | 利用者本人          | 注文履歴と CSV ログの突き合わせ                                |

## 4. 機能要件 (FR)

| ID    | 要件                                                                       | 優先度 |
|-------|----------------------------------------------------------------------------|--------|
| FR-01 | OANDA v20 REST から JP225_JPY の M5/H1/D1 ローソク足を取得できる           | Must   |
| FR-02 | 取得データで `aggregate()` を実行し、現在バーの合計スコアを算出できる      | Must   |
| FR-03 | スコアが `long_threshold` 以上で買い、`short_threshold` 以下で売り発注     | Must   |
| FR-04 | 発注時に ATR ベースの SL + RR 倍の TP を同時に設定する                     | Must   |
| FR-05 | 保有中、反対方向スコアが `opposite_exit_score` を超えたら手仕舞いする      | Must   |
| FR-06 | 日次損失 / 連敗 / 最大ロットのいずれかに抵触した場合、新規発注を停止する   | Must   |
| FR-07 | バーごとに 1 行 CSV 記録 (時刻 / スコア内訳 / NAV / アクション)             | Must   |
| FR-08 | `--dry-run` で発注を行わずに全フローを実行できる                           | Must   |
| FR-09 | `ping` / `candles` / `score-now` の単発診断コマンドを提供する              | Must   |
| FR-10 | プロセス停止シグナル (SIGINT/SIGTERM) を受けて安全に終了する               | Must   |
| FR-11 | API 5xx / 429 は指数バックオフで自動リトライする                           | Should |
| FR-12 | 1 日 1 回 (UTC 00:00) NAV 基準値をリセットする                             | Should |
| FR-13 | 複数銘柄並走 (1 プロセス / 1 銘柄)                                         | Could  |
| FR-14 | エントリー/エグジット時に Discord / Slack 通知                              | Could  |

## 5. 非機能要件 (NFR)

| ID     | 区分        | 要件                                                                 |
|--------|-------------|----------------------------------------------------------------------|
| NFR-01 | 可用性      | 平日 24h 連続稼働。週次再起動で問題ないこと                          |
| NFR-02 | 性能        | 1 バー処理 (3 TF fetch + score + decide) を 5 秒以内に完了           |
| NFR-03 | セキュリティ| API トークンは環境変数 / `.env` のみ。git 履歴に絶対残さない         |
| NFR-04 | 監査性      | 全アクション (HOLD 含む) が CSV に残る。注文 ID は `client_tag` で追跡|
| NFR-05 | 移植性      | Windows / macOS / Linux で動作 (Python 3.10+)                        |
| NFR-06 | 保守性      | バックテスト・MQL5 EA・ライブの 3 経路でスコア式が乖離しない        |
| NFR-07 | 復旧性      | プロセス再起動後、未約定の状態を引き継がない (毎バー再評価で十分)    |
| NFR-08 | コスト      | ホスティング月額 < 2,000 円 (VPS 最小プラン or 自宅 PC)              |

## 6. 制約条件

- OANDA Japan のレート制限: アカウントあたり 120 req/sec、20 req/sec バースト
- JP225_JPY 取引時間: 月曜 ~08:00 JST 〜 土曜 ~07:00 JST (週末・年末年始休止)
- OANDA の出来高は **tick volume** のみ (real volume は NULL)
- デモ口座でも約定価格は実マーケットを参照するが、デモ独自の遅延が発生し得る
- ライブ口座 API は別途利用申請が必要 (本プロジェクトのスコープ外)

## 7. 前提条件

- 利用者は OANDA Japan のデモ口座を保有し、API トークンを発行済み
- 実行ホストは Python 3.10+ がインストール済み
- 実行ホストから `api-fxpractice.oanda.com:443` へアウトバウンド接続が可能
- 実行ホストの時刻が NTP で同期されている (UTC 基準のバー境界計算に必須)

## 8. 範囲外 (Out of Scope)

- ライブ口座での実資金運用 (別案件)
- 複数 AS / 複数 OANDA アカウントでの並走
- バックテスト用パラメータの自動再チューニング (オフライン `tune.py` で別途実施)
- 機械学習モデルによるスコア合成 (現状は線形重み付け固定)
- ストリーミング価格 (現状はバー境界ポーリングのみ)

## 9. 受け入れ基準

- AC-01: `ping` コマンドが NAV と通貨を返す
- AC-02: `score-now` の合計スコアが、同じ時刻のオフライン backtest 結果と ±0.5 以内で一致
- AC-03: ドライ実行で 24h 連続稼働、欠損バー / 例外なしで CSV が連続出力される
- AC-04: デモ実発注で SL/TP がブラケットされたポジションが OANDA Web UI 上に表示される
- AC-05: SIGINT で 30 秒以内にプロセスが終了する
- AC-06: API トークンが `git log -p` および `git grep` で見つからない
- AC-07: 連敗 / 日次損失ガードが意図通り発火する (人為的に閾値を下げて検証)

## 10. リスクと対策

| ID    | リスク                                          | 影響 | 対策                                              |
|-------|-------------------------------------------------|------|---------------------------------------------------|
| R-01  | API トークン流出                                | 大   | `.env` gitignore、定期ローテーション              |
| R-02  | 環境変数を忘れて live モードに昇格              | 大   | `OANDA_ALLOW_LIVE=1` の二重ガード                 |
| R-03  | NTP ずれによるバー境界ミスマッチ                | 中   | OS の NTP 同期を有効化                            |
| R-04  | OANDA 障害で fetch 失敗                         | 中   | 指数バックオフ、ループ継続                        |
| R-05  | スコア計算結果が EA と乖離                      | 大   | デモ稼働中、毎日 CSV を `tune.py` 入力と突合      |
| R-06  | 過剰ポジション (バグで `units` が暴騰)          | 大   | `max_units_per_trade` のハード上限                |
| R-07  | 連敗時のドローダウン                            | 中   | `max_consec_losses` で自動ロック                  |
| R-08  | プロセス停止に気付かない                        | 中   | 将来 `heartbeat` を Discord 通知に流す (FR-14)    |
